The Property Search API returns ownership and resident information for a given property. Use it to identify property owners, find current residents, or verify property details.

## Make Your First Request

<Steps>
<Step>
### Send a Request

Search for property details by address:

```bash title="Request"
curl 'https://api.whitepages.com/v2/property/?street=STREET_ADDRESS&city=CITY&state_code=STATE_CODE' \
  --header 'X-Api-Key: YOUR_API_KEY'
```

Replace `YOUR_API_KEY` with your actual API key, and replace `STREET_ADDRESS`, `CITY`, and `STATE_CODE` with the address of the property you want to look up (URL-encode any spaces).

</Step>

## Match Confidence

Search ranks properties by how closely they match the address text you send, so
the closest match to an address that does not exist can be a different property
on the same street. Every response carries a `property_metadata` block saying
what you actually got.

```json
"property_metadata": {
  "confidence_score": 100,
  "match_type": "exact",
  "details_url": "/v2/property/RSAMPLE0001"
}
```

`match_type` is `exact` when the property is the address you searched for, and
`best match` when it is the closest thing found. `confidence_score` grades that
0–100:

| Score  | Meaning                                                   |
| ------ | --------------------------------------------------------- |
| `100`  | The property is the address you searched for              |
| `90`   | A different unit in the same building                     |
| `50`   | The closest match found, at a different address           |
| `25`   | The address you searched for is not a deliverable address |
| `null` | The address could not be checked                          |

The score compares standardized addresses rather than measuring search
relevance, so it answers "is this the property I asked for" rather than "how
well did this rank".

<Callout type="info">
  `confidence_score` and `match_type` are `null` when the address cannot be
  standardized — most often because the request carried no `street`, or carried
  a street with neither a `city` nor a `zipcode` to place it. The property is
  still returned.
</Callout>

## Returning Only Exact Matches — `strict_match=true`

If a wrong property is worse than no property — an automated pipeline, say, or
address verification — set `strict_match=true`. The API returns the address you
searched for or an address in the same building, and `404` when it finds
neither.

```bash title="Request"
curl 'https://api.whitepages.com/v2/property/?street=123%20Main%20Street&city=Seattle&state_code=WA&strict_match=true' \
  --header 'X-Api-Key: YOUR_API_KEY'
```

A result the API cannot verify is also dropped, because strict matching promises
nothing approximate comes back. `strict_match` needs a `street` to compare
against; a request without one returns `400`.

## Contact Limits on Owners and Residents

Each owner and resident carries up to **4 phone numbers** and **3 email
addresses**, highest confidence first. A metadata block on each person reports
what was held back and where the rest lives:

```json
"person_owner_metadata": {
  "details_url": "/v2/person/PSAMPLE0001",
  "phones": { "displayed": 2, "additional": 5 },
  "emails": { "displayed": 2, "additional": 1 },
  "owned_properties": { "displayed": 1, "additional": 3 }
}
```

`displayed` is how many came back on this response; `additional` is how many
more are linked to that person. Follow `details_url` to
[Person Details](/references/person-v2/get_person_by_id_v2) for the complete
lists. Owners carry `person_owner_metadata` and residents carry
`resident_metadata`; the contents are identical.

<Callout type="info">
  `owned_properties.additional` counts other properties the person owns, bounded
  by how many the search can retrieve at once. A person who owns a large
  portfolio reports fewer than they hold. Phone and email counts are exact.
</Callout>

## Request Parameters

| Parameter      | Required | Description                                                  | Example           |
| -------------- | -------- | ------------------------------------------------------------ | ----------------- |
| `street`       | No\*     | Street address                                               | `123 Main Street` |
| `city`         | No\*     | City name                                                    | `Seattle`         |
| `state_code`   | No\*     | Two-letter state code                                        | `WA`              |
| `zipcode`      | No\*     | ZIP code                                                     | `98101`           |
| `strict_match` | No       | Return only the address supplied or one in the same building | `true`            |

<Callout>
  At least one parameter is required. Include multiple parameters for more
  precise results.
</Callout>

**Example with ZIP code:**

```
https://api.whitepages.com/v2/property/?street=123%20Main%20Street&zipcode=98101
```

**Example by property ID:**

```
https://api.whitepages.com/v2/property/RSAMPLE0001
```

## Property Details by ID

The property details endpoint accepts either a Whitepages property ID (`R` prefix) or an address ID (`A` prefix). Address IDs are resolved to the associated property before lookup, so you can pass the address IDs found throughout other API responses directly:

```
https://api.whitepages.com/v2/property/{property_id_or_address_id}
```

<Callout type="info">
  Not every address ID has full property details, so lookups by address ID may
  return `404`. These responses are not billed — see
  [Billing](/references/billing) — so you can optimistically look up property
  details for any address ID you encounter.
</Callout>

## Address Standardization

Property addresses (both physical and mailing) are **not** processed through CASS certification. Property address data is sourced directly from county assessor and recorder records and is stored as-received without USPS standardization.

The address **you search with** is standardized, so that the response can tell
you whether the property returned is the one you asked for. That standardized
form is used only for the comparison behind `property_metadata` and
`strict_match` — it never changes the address values in the response, which
remain as the county recorded them.

<Callout type="info">
  For person address standardization details, see [Search by
  Address](/documentation/person-search/search-by-address#address-standardization-cass).
</Callout>
