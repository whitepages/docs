`GET /v2/phone/{phone}` answers **what is this number** — its line type and
carrier, and the people and businesses associated with it. Use it when the
number itself is the subject of your question.

<Callout type="info" title="Looking to rank people instead?">
  If a person is the subject and the number is one of your search criteria, use
  [Reverse Phone Lookup](/documentation/person-search/reverse-phone-lookup)
  instead. That guide ranks person records against a number; this one answers
  what the number is.
</Callout>

## Look up a number

```bash title="Request"
curl 'https://api.whitepages.com/v2/phone/12065550142' \
  --header 'X-Api-Key: YOUR_API_KEY'
```

### A switchboard

A company line collects everyone who has ever listed it, so `people` can be
long while the number belongs to the business. This is the case
`primary_owner` exists for: it reports `business` even though ten person
records came back.


### Spellings

Any common spelling addresses the same number. These four are one resource and
return one body:

```
/v2/phone/12065550142
/v2/phone/2065550142
/v2/phone/(206)%20555-0142
/v2/phone/%2B1-206-555-0142
```

The canonical form comes back in the `Content-Location` response header and is
itself callable, so a client that normalises on its own side can follow it
instead of writing its own rules.

The endpoint covers the North American Numbering Plan: an area code and
exchange starting with 2-9, followed by four digits. A number that doesn't
fit that shape is refused with HTTP 400 rather than searched. A number that
fits the shape but isn't a real assigned line — a reserved code like
`911` or `411` used as an area code or exchange, for instance — is
searched like any other and comes back with `primary_owner: "unknown"`
and empty `people` and `businesses`, the same as any other number nobody
is associated with. Each successful lookup bills one unit, whether or not
it found anyone.

## Reading the response

### `phone` — the number's own facts

Present on every successful response, including one where nothing is
associated with the number. `line_type` is one of `mobile`, `landline`,
`voip`, `tollfree`, or `unknown` when it can't be determined. `carrier` is
resolved by lookup where one is on file, and comes back `null` wherever
the provider has none — that isn't limited to toll-free numbers, so don't
assume a `null` carrier means toll-free.

A lookup that finds no parties is an answer, not an error — the `phone`
block is still populated.

### `primary_owner` — which list to read first

`person`, `business`, or `unknown`.

<Callout type="info" title="A kind, not a pointer">
  `primary_owner` classifies the line, and `business` can appear alongside a
  long `people` list or an empty `businesses` list. A switchboard collects
  everyone who ever listed it, so people count is a poor signal of ownership.
  Read it as a kind and use both lists.
</Callout>

### `businesses`

A business carries its name and, where one is known, its street address. Where
no street address is known it carries `approximate_locations` instead: the
postal code or city the business is placed within, with `precision` naming how
closely. The two lists do not overlap — a location is an address or it is
approximate.

### `people`

Person records in the same shape person search returns. `match_score` and
`matched_by` appear on every record and are inert here: there is no query for a
result to be relevant to.

`returned_people` is how many this response carries, `people_limit` is the
ceiling that applied, and `people_truncated` says the ceiling was reached.
Truncated with ten returned means at least ten are associated and the true
figure is unknown.

## Choosing between them

| If you want to…                                              | Use                                                                       |
| ------------------------------------------------------------ | ------------------------------------------------------------------------- |
| Know the line type or carrier                                | Phone Search                                                              |
| Find the business behind a number                            | Phone Search                                                              |
| Get an answer even when nobody is associated with the number | Phone Search                                                              |
| Rank people against the number                               | [Reverse Phone Lookup](/documentation/person-search/reverse-phone-lookup) |
| Confirm a number belongs to a named person                   | [Reverse Phone Lookup](/documentation/person-search/reverse-phone-lookup) |
| Combine the number with an address or age filter             | [Reverse Phone Lookup](/documentation/person-search/reverse-phone-lookup) |

Each successful lookup bills one unit on either endpoint, whether or not it
found anyone.
