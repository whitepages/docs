The Property API returns property records sourced from county assessor and recorder data, along with the owners and residents associated with each one. Use it to identify an owner, pull the full record for a property you already know, or find every property matching an address, a parcel number, or a map radius.

## Owner details or property details?

Start from what you want back. Looking for the owner, use `owners`. Looking
for the property, use a search or a details lookup.

`owners` accepts an address, a parcel number, or a property ID, so when
ownership is the question you rarely need a lookup first.

| Endpoint                  | Answers                                          | Returns                                                       |
| ------------------------- | ------------------------------------------------ | ------------------------------------------------------------- |
| `GET /v3/property/owners` | Who owns this property                           | Owner lists, how complete they are, and which parcel answered |
| `GET /v3/property/{id}`   | Everything on record for a property you can name | The full property record, ownership among it                  |
| `GET /v3/property/`       | Which properties match this query                | A ranked page of property records                             |

A property record carries an `ownership_info` block, so a search or a details
lookup names the owner too. The difference is what each one reports about that
answer. `owners` tells you whether the owner list is whole, through a
`complete` flag on each list, and which parcel it resolved to when an address
covers more than one. Neither of the other two reports either, and a search
result trims its owner and resident lists to five apiece.

Going the other way, `owners` returns only enough of the property to identify
it — address, parcel number, identifiers, and the match fields. For square
footage, ask for the property. For assessed value or mortgage history, ask for
it by identifier: a search leaves those two blocks `null`.

## Make your first request

<Steps>
<Step>
### Send a request

Search for a property by address:

```bash title="Request"
curl 'https://api.whitepages.com/v3/property/?street=123%20Main%20Street&city=Seattle&state_code=WA' \
  --header 'X-Api-Key: YOUR_API_KEY'
```

Replace `YOUR_API_KEY` with your API key, and the address parts with the property you want. URL-encode any spaces.

</Step>

## Request parameters

| Parameter      | Description                                              | Example           |
| -------------- | -------------------------------------------------------- | ----------------- |
| `street`       | Street address including number and name                 | `123 Main Street` |
| `city`         | City name                                                | `Seattle`         |
| `state_code`   | Two-letter state code                                    | `WA`              |
| `zipcode`      | ZIP code                                                 | `98101`           |
| `apn`          | Assessor parcel number                                   | `197500-0015`     |
| `fips`         | Five-digit county FIPS code                              | `53033`           |
| `lat` / `lng`  | Center point for a radius search                         | `47.60621`        |
| `radius`       | Radius in miles around `lat`/`lng`, up to 50 (default 1) | `2`               |
| `strict_match` | Return only results that match the address you supplied  | `true`            |
| `page`         | Page number, starting at 1                               | `2`               |
| `page_size`    | Results per page, up to 25 (default 10)                  | `25`              |

A search needs something to search on: a parcel number, at least one of `street`, `city`, or `zipcode`, or a `lat`/`lng` pair. `state_code` and `fips` narrow a search rather than defining one, so neither works on its own. Parameters combine with AND logic, so each one you add narrows the result set.

## Response codes

| Status                  | Description                                                       | Billable |
| ----------------------- | ----------------------------------------------------------------- | -------- |
| `200 OK`                | Request successful                                                | Yes      |
| `400 Bad Request`       | Missing or invalid parameters                                     | No       |
| `403 Forbidden`         | Invalid API key                                                   | No       |
| `404 Not Found`         | Nothing matched                                                   | No       |
| `409 Conflict`          | Parcel number names more than one property, on owners and details | No       |
| `429 Too Many Requests` | Rate limit exceeded                                               | No       |
| `5xx`                   | Server error                                                      | No       |

<Callout type="info" title="A search that finds nothing is free">
  Every endpoint in `/v3/property` bills on `200` and nothing else. A search
  that matches no property returns `404` and is not charged, so you can probe
  speculatively without spending credits on misses. This differs from `GET
  /v2/property/`, where a `404` is billed. See [Billing](/references/billing).
</Callout>

A `404` from `GET /v3/property/` carries the same envelope a match would, with an empty `results` array. One parser handles both outcomes.

Search answers `400` rather than `409` when parameters conflict, such as a parcel number combined with address parts or with a `lat`/`lng` pair. Each names one property a different way, and the API does not choose between them.

## Address standardization

Property addresses, both physical and mailing, are **not** processed through CASS certification. Property address data comes from county assessor and recorder records and is stored as received, without USPS standardization.

<Callout type="info">
  For person address standardization, see [Search by
  Address](/documentation/person-search/search-by-address#address-standardization-cass).
</Callout>
