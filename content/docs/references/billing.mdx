API usage is tracked and billed based on successful requests.

<Callout type="warn" title="Policy change effective June 1, 2026">
  The billing rules below apply to usage from June 1, 2026 onward. For usage on
  or before May 31, 2026, see the [Billing Policy For Usage Prior to
  2026-06-01](/references/billing-prior-to-2026-06-01).
</Callout>

## Billing rules

| Response Type      | Billable                                                           |
| ------------------ | ------------------------------------------------------------------ |
| 2xx (Success)      | Yes                                                                |
| 404 (Not Found)    | Yes, except on `/v3/property` and `GET /v2/property/{property_id}` |
| 409 (Conflict)     | No                                                                 |
| 400 (Bad Request)  | No                                                                 |
| 403 (Forbidden)    | No                                                                 |
| 429 (Rate Limit)   | No                                                                 |
| 5xx (Server Error) | No                                                                 |

<Callout type="info">
  All Person, Phone, and Property endpoints are billable, across every API
  version. Account, Regions, Events, and Webhooks endpoints are not billable.
</Callout>

### Property V3 bills only on a result

Every endpoint under `/v3/property` charges for `200` and nothing else:

| Endpoint                        | `200`  | `404` | `409`            |
| ------------------------------- | ------ | ----- | ---------------- |
| `GET /v3/property/`             | Billed | Free  | _(not returned)_ |
| `GET /v3/property/owners`       | Billed | Free  | Free             |
| `GET /v3/property/{identifier}` | Billed | Free  | Free             |

A search that matches nothing, an identifier with no property behind it, and a
parcel number that names several properties all cost nothing. You can probe an
uncertain address, try an address ID you are not sure about, or resolve a
parcel number through a `409` and pay only for the call that returns a
property.

This differs from V2, where a `404` from `GET /v2/property/` is billed. See
[Property V2 → V3](/references/migration/property-v2-to-v3).

## Billable requests

The following responses from Person and Property endpoints, in any API version, are charged to your account:

- All `2xx` (success) responses
- `404` (not found) responses, except on any `/v3/property` endpoint and on
  `GET /v2/property/{property_id}`

## Non-billable requests

The following responses are **not** charged:

- `400` (bad request) responses - missing or invalid parameters
- `403` (forbidden) responses - even when an API key is provided
- `404` (not found) responses on any `/v3/property` endpoint and on
  `GET /v2/property/{property_id}`
- `409` (conflict) responses - a parcel number naming several properties
- `429` (rate limit) responses - when you've exceeded rate limits
- `5xx` (server error) responses - issues on our end

### Property details lookups and 404s

`GET /v3/property/{identifier}` and `GET /v2/property/{property_id}` both accept a Whitepages property ID (`R` prefix) or an address ID (`A` prefix); the V3 route also accepts a parcel number. Not every address ID has full property details, so these lookups may return `404`. Because `404` responses on these endpoints are never billed, you can optimistically look up property details for the address IDs you encounter throughout other API responses.

## Billing period

Usage is calculated from the start of the month in UTC time. Your billing cycle resets on the 1st of each month at 00:00 UTC.

## Usage reports

Detailed usage reports are available through the [Account Usage](/references/account/get_account_usage_data) endpoint. You can query:

- Daily request counts
- Usage over custom date ranges (up to 90 days)
- Total requests for a time period
